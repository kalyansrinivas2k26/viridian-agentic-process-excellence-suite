# Who's Looking At This — Start Here By Role

> Eleven reviewer personas realistically open this repository. Each row tells you exactly which file to open first, what you're actually verifying, and what would make you close the tab. This document adds no new claims — every number and status below is already stated elsewhere in the repository; this just routes each reader to it directly instead of making them dig.

| Role | Open first | What you're actually checking | What would make you close the tab |
|---|---|---|---|
| **Recruiter (15 seconds)** | Root `README.md` | Does the top of the page answer: what problem, what result, what's still missing? | No business-outcome sentence in the first screen, or a maturity claim with no limitation next to it |
| **Non-technical hiring manager** | [`docs/PLAIN_LANGUAGE_SUMMARY.md`](PLAIN_LANGUAGE_SUMMARY.md) | The one-sentence problem, the four-step "what it does," and the honest "what this is not yet" section | Jargon with no plain-English translation, or a claim with nothing to check it against |
| **Engineering hiring manager (60 seconds)** | Project [`README.md`](../README.md) → [`docs/ARCHITECTURE.md`](ARCHITECTURE.md) | Whether the 6-stage pipeline (measurement → AI judgment → critique → validation → routing → report) is real and node-by-node traceable, not just a diagram | A mermaid diagram with no matching node list, or a "validated" claim with no run date/figures attached |
| **Salesforce architect** | [`docs/DEPLOYMENT.md`](DEPLOYMENT.md) → `workflows/Salesforce-Governance-Sentinel-v1.3-public.json` | OAuth 2.0 Client Credentials, dedicated API-only integration user, least-privilege permission set, `NamespacePrefix = null` managed-package exclusion — all four, not just asserted but present in the actual workflow config | Any node reading beyond Flow metadata scope, or credentials referenced anywhere outside n8n's credential store |
| **n8n / workflow engineer** | [`docs/ARCHITECTURE.md`](ARCHITECTURE.md) → the workflow JSON directly | That `Calculate DPMO - Flows` has no upstream AI node, and that `Validate Final Output Schema` sits between the AI critique and every downstream consumer | An AI node with a write path into the DPMO/Sigma calculation, or a routing branch with no fail-closed destination |
| **AI-governance / responsible-AI reviewer** | [`docs/SECURITY_THREAT_MODEL.md`](SECURITY_THREAT_MODEL.md) → [`docs/GOVERNANCE_REGISTERS.md`](GOVERNANCE_REGISTERS.md) | The OWASP LLM risk table (prompt injection, insecure output handling, excessive agency) with each risk mapped to a real control, and the decision-rights table proving AI can't self-approve | A risk marked "mitigated" with no evidence status, or "control documented" being presented as "control tested" |
| **Six Sigma / process excellence reviewer** | [`docs/METHODOLOGY.md`](METHODOLOGY.md) | DPMO 333,333.33 and Sigma 1.931 with their unit (1 Flow), defect definition (missing description), and opportunity denominator (3 per Flow, 21 total) all in the same place — and that Cpk is explicitly excluded with a stated reason | Any DPMO/Sigma figure quoted without its denominator anywhere in the repo, or a Cpk claim with no specification limits behind it |
| **PMP / delivery governance reviewer** | [`docs/PMP_AI_GOVERNANCE_MAPPING.md`](PMP_AI_GOVERNANCE_MAPPING.md) → [`docs/AGILE_TRACEABILITY.md`](AGILE_TRACEABILITY.md) | Each of the 9 PMI AI-standard areas maps to a named artifact (not a paragraph), and that AI-drafted remediation stories never carry story points, velocity, or sprint-commitment authority | A mapping row citing a file that doesn't exist, or any wording implying AI assigned story points or committed work |
| **Security reviewer** | [`SECURITY.md`](../../../SECURITY.md) (root) → [`docs/SECURITY_THREAT_MODEL.md`](SECURITY_THREAT_MODEL.md) | The 6 named threats (T1–T6), each with mitigation and residual risk stated separately — and that `scripts/validate_portfolio.py` actually runs a secret-pattern scan, not just claims to | A threat with a mitigation but no stated residual risk (that's the tell for an unreviewed control) |
| **CEO / business stakeholder** | [`docs/PLAIN_LANGUAGE_SUMMARY.md`](PLAIN_LANGUAGE_SUMMARY.md) → [`docs/EXECUTIVE_BRIEF.md`](EXECUTIVE_BRIEF.md) | The one-line pitch, the "why this is meaningful" section, and Section 6 ("What This Doesn't Prove Yet") — read that section specifically before believing Section 5 | A brief with no Section 6, or Section 6 written to minimize rather than state plainly |
| **CI / release auditor** | `.github/workflows/portfolio-validation.yml` → [`docs/FINAL_SIGNOFF_GATES.md`](FINAL_SIGNOFF_GATES.md) | Whether the repository claims a green run it hasn't actually had — check the Actions tab directly, don't trust the README | Any "CI Green" or "100/100" claim without a link to an actual passing public run |

## If you only have time for one file

[`docs/EVIDENCE_INDEX.md`](EVIDENCE_INDEX.md) — it's the map. Every other document above traces back to something listed there, with an explicit column for what each artifact does and does not prove.

## If you're deciding whether to trust this repository at all

Open [`docs/QUALITY_SCORECARD.md`](QUALITY_SCORECARD.md)'s "Score history" section first. A portfolio that shows you where its own score went *down* on independent review, and why, is giving you the fastest possible signal that its other claims are checkable rather than asserted.
